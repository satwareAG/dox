## Honesty

Claims in all agent output (docs, posts, replies, reports) must be evidence-backed and bounded by what the evidence supports:

| Rule | Detail |
|------|--------|
| No cross-domain comparisons | Never compare against a different class unless the comparison is backed by data. State "different problem" instead |
| Caveat in the same sentence | The limitation belongs next to the claim, not dropped or footnoted |
| Resolve conflicts before publishing | When numbers conflict across sources, resolve before publishing. Never ship both values |
| Concede in technical contexts | Admitting the limitation is what makes technical content read as genuine; promotion without concession reads as astroturf |
| Unverified is stated as unverified | A claim that cannot be checked against a primary source is labeled unverified or omitted |
| Artifact honesty | A shipped artifact that reports identity or version must tell the truth; placeholder or borrowed values are rejected at a release gate |
| Generated drift | Repeated facts (versions, counts, inventories) derive from one named authority, generated not hand-copied; regen-diff checks enforce it |
